# AI 可穿戴视觉上下文技术架构

## 1. 总体架构

整体采用三层架构：

```
Wearable Perception Module
        ↓
Phone Companion Runtime
        ↓
AI / Cloud Service
```

核心原则：

> 可穿戴端负责感知，手机负责上下文，AI 模型负责理解与推理。

不在第一阶段把复杂 AI 放进 wearable。

---

# 2. Wearable Perception Module

主要组件：

```
Camera
IMU
MCU / SoC
Wireless
Battery
```

主要职责：

- 图像采集
    
- IMU 采样
    
- Camera 唤醒
    
- 基础场景变化检测
    
- Frame Buffer
    
- 无线数据传输
    
- 功耗管理
    

不负责：

- OCR
    
- VLM
    
- LLM
    
- 长期记忆
    
- 任务推理
    

---

# 3. 推荐 Garage Demo 硬件

第一版建议：

### 主模组

2 × Seeed XIAO ESP32S3 Sense 或同等级小型 Camera 开发板

优势：

- Camera
    
- Wi-Fi
    
- 小尺寸
    
- 开发方便
    

---

### Battery

300–500mAh LiPo

---

### IMU

可选：

- BMI270
    
- ICM-42688
    
- LSM6DSO
    

第一版甚至可以暂不安装。

---

### Audio

不做在 perception module 中。

直接使用：

- AirPods
    
- 普通 Bluetooth Earbuds
    

语音输入和语音输出均可走手机 + 耳机。

# 4. 三种安装夹具

同一个电子模块设计三种机械附件：

### Glasses Mount

固定在眼镜腿。

### Ear Mount

耳挂形式，Camera 位于耳朵前外侧。

### Collar Mount

固定在衣领或胸口。

要求：

三种安装方式只改变位置，不改变 Camera 参数。

---

# 5. Camera 软件状态

Camera 分为三个模式。

---

## Observe Mode

目标：

持续感知，但最低功耗。

参数建议：

```
低分辨率
0.1–1 fps
```

功能：

- scene change
    
- motion
    
- brightness change
    
- context snapshot
    

不上传 Cloud。

---

## Context Mode

触发条件：

- 用户开始说话
    
- 明显转头
    
- 场景变化
    
- App 请求
    

执行：

```
capture 1–3 frames
↓
send to phone
↓
AI inference
```

---

## Capture Mode

显式用户请求：

> “拍下来。”

使用：

- 高分辨率
    
- JPEG
    
- 持久保存
    

与 AI 感知语义分开。

---

# 6. IMU 驱动的 Camera 策略

IMU 用于减少无效 Camera 工作。

例如：

```
head rotation > 30°
↓
wake camera
↓
capture new frame
```

静止时：

```
camera sleep
```

避免：

持续 30fps 视频。

---

# 7. Visual Context Buffer

手机维护滚动视觉 Buffer。

例如：

```
T-30 sec
T-20 sec
T-10 sec
T-5 sec
T-2 sec
NOW
```

动态采样策略：

### 静止

1 frame / 10–30秒

### 明显运动

2–4 frames

### Voice Trigger

立即捕获：

```
T-3
T-1
NOW
T+1
```

# 8. Phone Companion Runtime

手机是核心运行平台。

模块：

```
Device Manager
Frame Receiver
Visual Buffer
Audio Manager
ASR
Context Manager
VLM Gateway
Memory Engine
LLM / Agent Runtime
TTS
Experiment Logger
```

---

# 9. Device Manager

负责：

- BLE/Wi-Fi pairing
    
- Camera 配置
    
- Frame 请求
    
- Battery status
    
- Firmware state
    

---

# 10. ASR

负责：

Speech → Text

Garage MVP 可采用：

- 手机本地 ASR
    
- 云端 ASR
    

目标：

尽量在用户说话同时并行抓取视觉帧。

---

# 11. Context Manager

系统核心。

维护：

```
current_visual_scene
recent_visual_history
current_task
recent_dialogue
user_query
motion_context
```

示例：

```
Task:
安装 Wi-Fi AP

Visual:
PoE switch
RJ45 cable
AP

Dialogue:
“这个要怎么供电？”

Motion:
用户刚低头
```

最终组合成 AI 请求。

---

# 12. VLM 调用

请求结构：

```
User Query
+
Current Frame
+
Selected Historical Frames
+
Task Context
+
Recent Dialogue
```

不是：

单图 + 单句 prompt。

---

# 13. Short-Term Visual Memory

视觉帧进入：

```
Frame
↓
Embedding
↓
OCR
↓
Scene Summary
↓
Timestamp
↓
Vector Index
```

示例：

```
14:32:10
scene: 会议室门口

objects:
key
black backpack

OCR:
Meeting Room 3
```

---

# 14. Visual Memory 查询

用户：

> “刚才那个标签写什么？”

处理：

```
Query
↓
Semantic Retrieval
↓
Candidate Frames
↓
VLM Re-ranking
↓
Answer
```

---

# 15. 数据保留策略

第一版建议：

Original Frame：

5–30 分钟自动删除。

保留：

- embedding
    
- timestamp
    
- OCR
    
- summary
    

如需长期保存必须显式触发。

---

# 16. Audio Pipeline

语音输入：

```
Earbuds Mic
↓
Phone
↓
ASR
```

输出：

```
LLM
↓
TTS
↓
Bluetooth Earbuds
```

Wearable Camera Pod 不处理 Audio。

优先 Wi-Fi。

- 带宽充足
    
- 调试方便

- BLE

# 22. 技术原则

第一阶段优先：

> 快速验证 Context UX

而不是：

- 极致尺寸
    
- 极致功耗
    
- 本地 AI
    
- 自定义 PCB
    

所有技术选择都应服务于：

> 快速验证用户是否真正需要这种交互。
